# Specification: Extended font variety in Excalidraw

**Issue:** [excalidraw/excalidraw#10834 — Adding more fonts to the list](https://github.com/excalidraw/excalidraw/issues/10834)  
**Status:** Phase 1 implemented in this fork (Lexend added as curated font); broader roadmap items remain open upstream.

## 1. Problem

The canvas font picker is intentionally small. Users want **more typographic variety** (including more handwritten / display styles), similar to pickers in tools like Figma or Canva. Today, adding a font is effectively a **code change**: register faces, metrics, and build assets—not something end users or hosts can extend without forking.

## 2. Goal

Expand user-selectable curated fonts for canvas typography while holding export layout parity across clients, license-compatible distribution for raster/vector exports, stable scene-open latency.

### 2.1 Product requirements (former G1–G4)

These items refine the goal; detailed functional/non-functional coverage lives in §6–§7.

- **Choice:** Offer a materially larger, curated set of fonts that fit Excalidraw’s use cases (diagrams, whiteboards, slides, code-adjacent labels).
- **Rendering consistency:** Text layout, export, and collaboration stay consistent across clients where fonts are available.
- **Licensing:** Every bundled or dynamically loaded font uses license terms compatible with distribution and embedding in PNG/SVG/PDF exports.
- **Performance:** Avoid regressions to initial load, scene open, or export time; lazy-load where possible.

## 3. Non-goals (initial scope)

- Full **arbitrary user font upload** on excalidraw.com without a separate security, storage, and abuse review.
- Parity with **entire** Google Fonts / system font lists without search, subsetting, and CDN strategy.
- Changing default fonts or removing deprecated families without a migration plan.

## 4. Current implementation (baseline)

Relevant areas in this codebase:

| Area | Role |
|------|------|
| `FONT_FAMILY` in `packages/common/src/constants.ts` | Numeric IDs for each family; comments already note future **non-integer / hash IDs** for custom fonts. |
| `FONT_METADATA` in `packages/common/src/font-metadata.ts` | Metrics, `deprecated`, `private`, `fallback` flags. |
| `Fonts` in `packages/excalidraw/fonts/Fonts.ts` | Registers `@font-face`-style loading via `ExcalidrawFontFace`, subsetting for export. |
| `FontPicker` / `FontPickerList` | Quick picks + searchable list; list excludes `private` and `fallback` fonts. |

**Implication:** “More fonts” is not only UI work; it touches **element schema** (`fontFamily`), **metrics**, **export embedding**, and possibly **`.excalidraw` / collaboration** compatibility.

## 5. Solution directions

### 5.A Curated expansion (bundle + register)

- Add new families like existing ones (WOFF2 assets, `ExcalidrawFontFace` descriptors, `FONT_METADATA` entries, i18n labels).
- **Pros:** Full control, offline-friendly, predictable export. **Cons:** Package size grows; each font needs legal review and maintenance.

### 5.B Dynamic font catalog (Figma/Canva-like)

- Host or proxy a **catalog** (metadata + WOFF2 URLs or subset API). Client loads faces on demand via `FontFace` / CSS.
- **Pros:** Scales to many fonts without bloating the default bundle. **Cons:** Network dependency, caching, CORS, licensing for hot-linked fonts, harder guarantees for export and embeds.

### 5.C Hybrid (recommended default to discuss)

- **Small curated set** in the bundle (current behavior + a few high-value additions).
- **Optional extended catalog** (feature-flagged or host-provided) for app integrators and excalidraw.com if infra allows.

### Changes Required (Phase 1)

**Mapping to §5 options**

- **In scope:** **§5.A — Curated expansion** only (bundle WOFF2, register faces, metrics, picker/i18n, export path).
- **In scope (partial §5.C):** the **“small curated set in the bundle”** bullet—no optional catalog work.
- **Out of scope:** **§5.B — Dynamic font catalog** (no hosted catalog, no on-demand `FontFace` from arbitrary URLs, no CDN/CORS strategy in this phase).
- **Out of scope:** the **“optional extended catalog”** bullet under **§5.C**; also **FR5 (integrator API)** and schema work in **§8** beyond continuing integer `fontFamily` for new built-ins.

Treat **`docs/specs/10834.md` as the scope contract** for Phase 1 PRs; if the implementation diverges, update this spec in the same change.

**Typical file / directory touch set (monorepo paths)**

| Path | Phase 1 role |
|------|----------------|
| `docs/specs/10834.md` | Spec + scope (this document). |
| `packages/common/src/constants.ts` | New `FONT_FAMILY` id(s). |
| `packages/common/src/font-metadata.ts` | New `FONT_METADATA` rows (metrics, `deprecated` / `private` / `fallback` as needed). |
| `packages/excalidraw/fonts/<FamilyName>/` | New folder: WOFF2 file(s) + `index.ts` face module (same pattern as `Lexend/`, `Nunito/`, …). |

| `packages/excalidraw/locales/*.json` | Picker / label copy for the new family. |

| `packages/excalidraw/tests/` (e.g. `tests/scene/export.test.ts`, `tests/data/restore.test.ts`, `components/FontPicker/FontPicker.test.tsx`) | Snapshots or assertions covering export / restore / picker for the new family. |

**Explicitly unchanged in Phase 1 (limit blast radius)**

- `excalidraw-app/` — no required changes for adding package-local curated fonts (collab, Firebase, Sentry, etc. stay untouched unless maintainers ask otherwise).
- `examples/` — no Phase 1 requirement.
- No new `packages/excalidraw` “integrations” layer or app-specific font loaders—those would belong to later phases tied to **§5.B** / **§5.C**.

## 6. Functional requirements

**FR1 — Discovery**  
Search/filter fonts by name; optional grouping (e.g. Handwritten, Sans, Mono, Display) if the list grows.

**FR2 — Selection**  
Choosing a font updates the active text style and persists on `ExcalidrawTextElement` in a way that survives save/reopen.

**FR3 — Deprecated / scene fonts**  
Preserve current behavior: fonts used in the scene remain selectable even if deprecated; align any new “catalog” fonts with the same rules.

**FR4 — Export**  
PNG/SVG/PDF (and any HTML export) must embed or reference fonts so output matches the canvas when technically possible; document limitations for dynamic-only fonts.

**FR5 — Integrator API**  
If the direction is extensibility, define how **embedders** (e.g. self-hosted apps) register extra fonts without patching `FONT_FAMILY` integers—aligns with existing TODOs around custom fonts in `constants.ts` / `Fonts.ts`.

## 7. Non-functional requirements

| ID | Requirement |
|----|-------------|
| NFR1 | **License:** OFL or equivalent for bundled fonts; documented attribution. |
| NFR2 | **Size:** Target max impact on bundle (set MB budget per phase). |
| NFR3 | **Latency:** Fonts not on the critical path for first paint; prefetch for likely picks optional. |
| NFR4 | **Accessibility:** Picker remains keyboard navigable; sufficient contrast for preview text. |
| NFR5 | **Privacy:** Dynamic loading must not leak scene content to third parties beyond agreed font endpoints. |

## 8. Data model & compatibility

- **Short term:** Continue numeric `fontFamily` for built-ins.
- **Medium term (if custom/dynamic):** Plan migration to **stable string IDs** (or hashed IDs) for catalog fonts; define fallback when an old client opens a file with an unknown ID (e.g. map to Excalifont + preserve original in JSON for round-trip).

## 9. Open questions for maintainers

1. **Product:** Is the priority “more built-ins” vs “pluggable catalog” vs both?
2. **Infra:** Will excalidraw.com host font files/CDN, or only third-party integrators?
3. **Legal:** Process for approving new OFL/google-fonts vs other licenses?
4. **Schema:** Timeline for moving off integer `fontFamily` for extensibility?
5. **Handwritten roadmap:** How does this align with the existing roadmap item on handwritten fonts—same picker, or a separate category?

## 10. Suggested phases

1. **Phase 1 — Curated:** Add N fonts (e.g. 3–5) with full metrics + export path; measure bundle delta.
2. **Phase 2 — UX:** Categories, better previews, optional “show more” without dynamic loading.
3. **Phase 3 — Extensibility:** Host/API for catalog + integrator registration + compatibility strategy for unknown fonts.

## 11. Acceptance criteria (example for Phase 1)

- New fonts appear in `FontPickerList`, pass i18n and a11y checks.
- New text elements round-trip through `.excalidraw` JSON and render correctly after reload.
- Export tests cover at least one new family (subset/embed behavior).
- License notices updated (e.g. package or `NOTICE` as per project convention).
