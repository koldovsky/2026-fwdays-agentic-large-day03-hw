# Spec: Markdown Hyperlinks in Text Elements (#11024)

## Goal

When a user types a markdown-style link `[label](url)` inside a text element and
finishes editing, the raw markdown syntax is replaced by the visible label text
and the element's `link` property is set to the URL. This makes the text element
act as a clickable hyperlink without introducing any new rendering or data-model
changes — it reuses the existing element-level `link` mechanism.

## Context

- Issue: [#11024](https://github.com/excalidraw/excalidraw/issues/11024)
- Currently `[label](url)` renders as plain text; users have no shorthand to
  turn a text element into a link.
- Excalidraw elements already have a `link: string | null` property that makes
  the element clickable (opens URL on Ctrl/Cmd-click). This feature piggybacks
  on that property.

## Scope

### In scope

1. **Parse** — extract `[label](url)` patterns from the raw text on submit.
2. **Resolve** — replace each markdown link with its label in the displayed text.
3. **Link** — set the element's existing `link` property to the first extracted
   URL (only the first link is used; the element-level link is a single value).
4. **Sanitize** — reject dangerous URL schemes (`javascript:`, `data:`) via the
   existing `normalizeLink` helper; leave the raw markdown intact for rejected
   URLs so the user can see and fix them.
5. **Edge cases** — empty label (fall back to URL as label), empty URL (no-op),
   balanced parentheses in URLs (Wikipedia-style), mixed safe and unsafe links
   in one text.

### Out of scope (non-goals)

- Rich / inline rendering of links (underline, color, per-word click targets).
  The link applies to the whole element, not to a span within the text.
- Support for other Markdown formatting (bold, italic, images, headings, etc.).
- Multi-link support at the element level. Only the first valid URL is used as
  the element `link`; remaining labels are still resolved into plain text.
- Changes to the text editing UX (WYSIWYG preview, autocomplete, toolbar, etc.).
- Changes to existing element-link behavior or UI.

## Design

### Data flow

```
User finishes editing
        │
        ▼
  parseMarkdownLinks(originalText)
        │
        ├── null  →  no change (plain text, no markdown links)
        │
        └── { resolvedText, links[] }
                │
                ▼
          updateElement(resolvedText, isDeleted, links[0].url)
                │
                ├── element.originalText = resolvedText  (label only)
                ├── element.link          = first URL
                └── element dimensions are recalculated
```

### Key module

| File | Role |
|------|------|
| `packages/excalidraw/utils/markdownLink.ts` | Pure function `parseMarkdownLinks` — regex extraction, URL sanitisation, label resolution. |
| `packages/excalidraw/components/App.tsx` (`handleTextWysiwygForTextElement`) | Integration point: calls parser on submit, passes resolved text and link to `updateElement`. |

### Regex

```
/\[([^\]]*)\]\(((?:[^()]*|\([^()]*\))+)\)/g
```

Supports one level of balanced parentheses in the URL segment so that
Wikipedia-style URLs like `https://en.wikipedia.org/wiki/Foo_(bar)` work.

### Security

URLs are passed through `normalizeLink` (from `@excalidraw/common`) which calls
`sanitizeUrl` → strips `javascript:`, `data:`, and other dangerous schemes,
returning `"about:blank"` for blocked values. The parser treats `about:blank` as
invalid and preserves the original markdown text so the user sees exactly what
they typed.

## Acceptance Criteria

1. Typing `[Excalidraw](https://excalidraw.com)` in a text element and
   confirming replaces the visible text with `Excalidraw` and sets the element
   link to `https://excalidraw.com`.
2. Multiple markdown links in one text element: all labels are resolved into
   plain text; the element `link` is set to the **first** valid URL.
3. `[label](javascript:alert(1))` is left as raw markdown (not resolved, no
   link set) — same for `data:` URLs.
4. In mixed text with both safe and unsafe links, only safe links are resolved;
   unsafe ones stay as-is.
5. Empty label `[](https://example.com)` falls back to the URL as visible text.
6. Empty URL `[label]()` is a no-op (text unchanged).
7. Plain text without any markdown links is unaffected.
8. All existing tests pass (`yarn test:update`).
9. Type-check passes (`yarn test:typecheck`).

## Test Plan

Unit tests live in `packages/excalidraw/tests/markdownLink.test.ts` and cover:

- Standalone link parsing (single link = entire text)
- Inline links within surrounding text
- Multiple links in one string
- Edge cases: empty label, empty URL, relative URLs, query strings, hashes,
  balanced parentheses
- Null return for plain text, empty string, bare URLs
- Security: `javascript:` and `data:` URL rejection
- Mixed safe + unsafe links in one string
