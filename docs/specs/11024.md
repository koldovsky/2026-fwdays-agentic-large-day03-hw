# Spec: Inline Markdown Hyperlinks in Text Elements

**Issue:** [excalidraw/excalidraw#11024](https://github.com/excalidraw/excalidraw/issues/11024)
**SDD Approach:** Simple Markdown spec (`docs/specs/<issue-number>.md`)
**Author:** Day 3 Workshop
**Date:** 2026-04-03

---

## Why Simple Markdown?

This feature is a self-contained rendering enhancement with a clear scope and no impact on persisted data formats or public API contracts. A simple Markdown spec is sufficient because:
- The change touches ≤ 3 files (utility + renderer + click handler)
- No new element types or schema migrations are needed
- Acceptance criteria are enumerable and testable

---

## Problem Statement

Excalidraw text elements currently display raw text only. Users who type `[label](https://example.com)` see the literal characters on the canvas. There is no way to embed clickable inline hyperlinks within text content without attaching a single link to the entire element.

**Use cases:**
- Diagrams that reference external docs, tickets, or design files
- Presentation-ready canvases where links are embedded in context

---

## Goal

Detect markdown-style link syntax `[label](url)` inside text elements and render the label portion with hyperlink styling (blue color, underline). Clicking the label in view/default mode opens the URL in a new tab.

---

## Non-goals (out of scope for this PR)

- Hiding the `(url)` part — text content and metrics remain unchanged; full visual transformation is a follow-up
- Editing mode (wysiwyg) link preview — raw syntax is shown in the editor
- `ftp://` or other non-http(s) schemes
- Nested or escaped markdown syntax

## Technical Design

### 1. Data model

No changes. Text is stored as-is (including `[label](url)` syntax) in `ExcalidrawTextElement.text` and `originalText`. Element dimensions are computed from the full raw text width, preserving existing layout behavior.

### 2. New utility: `parseMarkdownLinks`

**File:** `packages/element/src/markdownLinks.ts`

```ts
export interface TextSegment {
  type: "text" | "link";
  content: string;  // displayed text (for links: the label)
  url?: string;     // only for type === "link"
  rawLength: number; // chars in original text this segment covers
}

// Parses one line of text into segments.
// "[foo](https://x.com) bar" →
//   [{type:"link", content:"foo", url:"https://x.com", rawLength:22},
//    {type:"text", content:" bar", rawLength:4}]
export function parseMarkdownLinks(line: string): TextSegment[]

export function isAllowedUrl(url: string): boolean // http(s) only
```

### 3. Canvas rendering

**File:** `packages/element/src/renderElement.ts`

In the text rendering block (currently lines 585–591), replace the simple `context.fillText(lines[index], ...)` call with segment-aware rendering:

1. For each line, call `parseMarkdownLinks(line)` to get segments.
2. Track cumulative x-offset using `context.measureText(segment.content).width`.
3. For `"text"` segments: render with element's `strokeColor`.
4. For `"link"` segments:
   - Set `fillStyle` to `LINK_COLOR` (`#2563EB`)
   - Draw text
   - Draw underline with `fillRect(x, baseline+2, width, 1)` scaled by `element.fontSize / 20` for thickness
   - Restore original `fillStyle`

### 4. Inline link click detection

**File:** `packages/excalidraw/components/App.tsx`

New private method `getInlineMarkdownLinkAtPoint(element, scenePoint)`:

1. Compute point relative to element origin (accounting for rotation via `rotate()`).
2. `lineIndex = Math.floor(relY / lineHeightPx)` — determine which line.
3. Parse that line into segments; walk segments measuring cumulative width.
4. Return `url` if `relX` falls within a link segment's x-range, else `null`.

Integrate into `handleElementLinkClick`:
- After the existing element-level link check, if no element link was hit AND the clicked element is a text element, call `getInlineMarkdownLinkAtPoint`.
- If a URL is returned, open it (same `window.open` + `noopener` pattern as existing link handling).

### 5. Security

- `isAllowedUrl` validates scheme is `http:` or `https:` only.
- `window.open` uses `rel=noopener` (already done by existing pattern: `newWindow.opener = null`).
