# Specification: Invalid hex feedback in color picker

## Goal

Show a clear inline error when the hex code field in the color picker contains a value that is not a valid hexadecimal color, instead of failing silently.

## Context

- **Issue:** https://github.com/excalidraw/excalidraw/issues/9527  
- **Labels:** `enhancement`, `good first issue`, `UX/UI`  
- **Current behavior:** Invalid hex-like input (wrong length, non-hex letters, etc.) does not call `onChange`; the stroke/fill color stays the same and the user gets no explanation.  
- **Expected behavior:** Visible, accessible error text under the hex field, with distinct messages for “wrong length” vs “invalid characters”, matching the examples in the issue.

## Component / Module

| Area | Files |
|------|--------|
| Pure validation | `packages/common/src/colors.ts` — `validateHexColorFieldInput` |
| Unit tests (validation) | `packages/common/src/colors.test.ts` |
| UI | `packages/excalidraw/components/ColorPicker/ColorInput.tsx` |
| Styles | `packages/excalidraw/components/ColorPicker/ColorPicker.scss` |
| i18n | `packages/excalidraw/locales/en.json`, `packages/excalidraw/locales/uk-UA.json` |

## Changes Required

1. **`validateHexColorFieldInput`**  
   - Trim input; strip optional leading `#` for validation.  
   - **Empty** after trim → `{ status: "empty" }` (no error, no commit).  
   - Body must be only `[0-9a-fA-F]+`; otherwise `{ status: "invalid", reason: "chars" }`.  
   - Length must be 3, 4, 6, or 8; else `{ status: "invalid", reason: "length" }`.  
   - If syntactically valid, confirm with existing `normalizeInputColor("#" + body)`; if that returns `null`, treat as `chars`.  
   - On success return `{ status: "valid", normalized }`.

2. **`ColorInput`**  
   - On each change, run the validator instead of `normalizeInputColor` alone.  
   - Valid → `onChange(normalized)`, clear error.  
   - Invalid → show error, do not call `onChange`.  
   - Empty → clear error, update local display only.  
   - On blur → restore `innerValue` from `color` prop and clear error (same reset behavior as before, plus error cleared).  
   - `aria-invalid`, `aria-describedby`, `role="alert"` on the error line.

3. **Styles**  
   - Wrapper `.color-picker__input-field` holds row + error (margin moved from inner row to wrapper so layout stays consistent).  
   - Error state: border/shadow using `var(--color-danger)`; small error text below.

4. **i18n**  
   - `colorPicker.hexError.invalidLength` and `colorPicker.hexError.invalidChars` in `en.json` (source of truth for keys) and Ukrainian in `uk-UA.json`.

## Non-goals

- Do not change the palette grid, eye dropper, or non-hex color formats outside this field’s validation rules.  
- Do not add toast/modal notifications; scope is inline feedback only.  
- Do not alter `normalizeInputColor` semantics for other call sites.  
- Do not require translations for all 58 locale files (runtime falls back to `en.json`).

## Acceptance Criteria

1. Entering `123456789`, `1`, `12`, `12345`, `1234567`, `zzzzzz`, or `blue` in the hex field shows an error and does not change the committed color until input is fixed or the field is blurred (blur restores the last committed color and clears the error).  
2. Entering valid hex lengths `3` / `4` / `6` / `8` (digits only) updates the color and clears any error.  
3. Empty or whitespace-only input shows no error and does not commit a new color.  
4. Error messages are translated via `t(...)` and the hex field exposes `aria-invalid` and `aria-describedby` when an error is shown.

## Edge Cases

- Pasted value with leading `#` — handled by stripping `#` before checks.  
- Mixed case — normalized to lowercase in the input handler before validation.  
- Parent `color` updates while the picker is open — `useEffect` resets local state and clears error.

## Constraints

- Reuse `normalizeInputColor` for final validity of hex strings so behavior stays aligned with tinycolor/Electron edge cases.  
- Keep validation in `@excalidraw/common` for unit testing without React.
