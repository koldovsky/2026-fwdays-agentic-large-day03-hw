# Spec: Add Keyboard Shortcut for Stroke Style Toggle

## Goal

Add a keyboard shortcut (`Alt+D`) that cycles stroke styles (solid → dashed → dotted) for the active tool default or selected elements.

## Component / Module

| File | Role |
|------|------|
| `packages/excalidraw/actions/actionProperties.tsx` | `actionChangeStrokeStyle` — add `keyTest`, modify `perform` to cycle on null value |
| `packages/excalidraw/components/HelpDialog.tsx` | Shortcut documentation in Tools section |
| `packages/excalidraw/locales/en.json` | `"labels.cycleStrokeStyle"` locale key |
| `packages/excalidraw/actions/actionProperties.test.tsx` | New tests for cycling behavior |

## Input / Props / Request

- **Keyboard event:** `keydown` with `altKey: true`, `code: "KeyD"`, `shiftKey: false`, `ctrlKey/metaKey: false`
- **AppState field:** `currentItemStrokeStyle: StrokeStyle` (`"solid" | "dashed" | "dotted"`)
- **Element field:** `strokeStyle: StrokeStyle` on selected elements
- **Action value:** `ExcalidrawElement["strokeStyle"] | null` — explicit value from UI, `null` from keyboard (triggers cycling)

## Output / Behavior

| Scenario | Result |
|----------|--------|
| `Alt+D`, no selection, `currentItemStrokeStyle = "solid"` | `currentItemStrokeStyle` → `"dashed"` |
| `Alt+D`, no selection, `currentItemStrokeStyle = "dashed"` | `currentItemStrokeStyle` → `"dotted"` |
| `Alt+D`, no selection, `currentItemStrokeStyle = "dotted"` | `currentItemStrokeStyle` → `"solid"` |
| `Alt+D`, rectangle selected with `strokeStyle = "solid"` | Element `strokeStyle` → `"dashed"`, `currentItemStrokeStyle` → `"dashed"` |
| UI radio button click passes explicit value (e.g. `"dotted"`) | Element + appState set to `"dotted"` (existing behavior, unchanged) |

## Edge Cases

- **Element without stroke style** (e.g. text, freedraw): `changeProperty` skips elements that don't have `strokeStyle` — existing behavior via `newElementWith` no-op
- **Mixed selection** (rectangle + text): only elements with `strokeStyle` are updated; `currentItemStrokeStyle` still cycles
- **Conflicting modifiers** (`Ctrl+Alt+D`, `Alt+Shift+D`): `keyTest` returns `false`, shortcut does not fire; `Alt+Shift+D` remains theme toggle
- **Rapid repeated presses**: each press cycles one step; no debounce needed (matches existing action pattern)
- **View mode**: `ActionManager.handleKeyDown` blocks actions with `viewMode !== true` — shortcut is inert in view mode

## Constraints

- **Shortcut is `Alt+D`**, not key `9` — `9` is already bound to Image tool (`shapes.tsx` line 97); reassigning it would break existing workflows
- **Uses existing action system** — `keyTest` on `actionChangeStrokeStyle`, intercepted by `ActionManager.handleKeyDown()` before `findShapeByKey()` pipeline
- **Variant A chosen** over Variant B (key `9` override) because it follows the standard `Alt+<letter>` toggle pattern (`Alt+Z` zen, `Alt+S` snap, `Alt+R` view) and requires no changes to tool-selection code
- **No new npm dependencies**

## Non-goals

- Do NOT reassign key `9` (Image tool)
- Do NOT add the "hold 9 + number" chord mechanism (complex, no existing pattern in codebase)
- Do NOT add animation/highlight to the floating bar (separate enhancement)
- Do NOT add customizable shortcut mappings (separate feature)
- Do NOT change existing stroke style UI behavior (panels, popovers, radio buttons)

## Acceptance Criteria

1. `Alt+D` with no selection cycles `currentItemStrokeStyle`: solid → dashed → dotted → solid
   - **Verify:** test asserts state after 3 sequential presses
2. `Alt+D` with selected elements cycles their `strokeStyle`
   - **Verify:** test creates rectangle, selects it, asserts `strokeStyle` after each press
3. `Alt+D` does not fire with `Ctrl` or `Shift` held
   - **Verify:** tests assert `currentItemStrokeStyle` unchanged after `Ctrl+Alt+D` and `Alt+Shift+D`
4. Shortcut appears in Help Dialog (`?` key) under Tools section
   - **Verify:** visual inspection; label uses `t("labels.cycleStrokeStyle")`
5. Existing UI (radio buttons) behavior unchanged — explicit `value` still passed directly
   - **Verify:** existing `actionStyles.test.tsx` and `contextmenu.test.tsx` tests pass
6. `yarn test:typecheck` passes with no new errors
7. All existing tests pass (`yarn test --watch=false`)
